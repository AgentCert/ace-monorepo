Step 1
App Catalog
Apps are the workloads agents operate against. Each app declares its domain and capabilities — this drives which faults appear in Chaos Studio automatically.
Two Onboarding Paths
Path A Helm-based (recommended)
Provide a public Helm chart URL + values.yaml. ACE installs into a fresh namespace per run. Zero cluster state persists between experiments.
helmRepochartNamevalues override
Path B Bring-your-own manifest
Raw Kubernetes YAML. ACE applies into isolated namespace. Suitable for apps not yet Helm-packaged.
app.yaml anatomy
apiVersion: ace.io/v1 kind: AppCatalogEntry metadata: name: sock-shop domain: cloud-native # fault filter key spec: description: "Microservices demo store" install: type: helm repoURL: "https://..." chart: sock-shop version: 1.2.0 capabilityDomains: - cloud-native - itops requiredCapabilities: - prometheus-query - kubernetes-get-pods healthCheck: endpoint: /health timeoutSecs: 120

Step 3
Fault Taxonomy
Three scopes of faults — from universal infrastructure failures down to app-specific edge cases. Scope determines who contributes the fault and who sees it in Chaos Studio.
ScopeWho contributesVisible toExamples
general ACE core team (PR to main repo) All apps, all domains pod-delete, network-delay, cpu-hog, disk-fill
domain Domain SMEs (PR to capabilities/) Apps in that domain 5g-nf-restart (telecom), cost-spike (finops), ehr-outage (health-it)
app-specific App owner (bundled with app.yaml) That named app only sock-shop/cart-db-corruption, litellm/model-timeout
Fault Spec (fault.yaml)
scope: general # general | domain | app-specific spec: implementation: type: litmus # litmus|http-fault|script|external experimentRef: pod-delete groundTruth: category: availability detectWithinSecs: 60 mitigateWithinSecs: 120
Four Implementation Types
litmus
LitmusChaos ChaosEngine CRD. Standard infra faults (pod-delete, network-latency, cpu-hog).
http-fault
API-level errors injected via Envoy or Istio. 5xx responses, timeouts, malformed payloads.
script
Custom injector image. Shell script or Go binary. Full control for domain-specific faults.
external
Calls an external API to trigger fault. Integrates with existing chaos platforms or vendors.
Step 3 cont.
Experiment Execution
An ExperimentDefinition is a reusable blueprint. Each run is an immutable record with its own namespace, model, and Langfuse trace ID.
ExperimentDefinition schema
kind: ExperimentDefinition spec: targetApp: sock-shop hypothesis: "Agent detects pod failure" modelSelection: mode: agent-default # agent-default|fixed|user-chooses-at-run steps: - name: baseline type: observe duration: 30s - name: inject-pod-fail type: fault faultRef: pod-delete groundTruthOverride: detectWithinSecs: 45 successCriteria: overall: toolCallEfficiencyMin: 0.7
Step Types
observe Agent runs freely; no fault active. Baseline window.
fault Fault injected. Ground truth window starts.
verify Assert health probe passes post-remediation.
wait Pause for stabilisation between steps.
parallel-fault Multiple faults simultaneously. Cascading failure simulation.
Model Selection Modes
agent-default
Use whatever model the agent's llmConfig declares.
fixed
Pin a specific model for this experiment. All runs use it.
user-chooses-at-run
Run dialog shows model picker from allowedModels list.
Step 4
Certifier Pipeline
LLM-as-judge over two data streams. No agent code changes required. Third-party agents are scored purely from observable behavior.
Inputs
Two Streams
  • Stream 1: fault events + timestamps
  • Stream 2: Langfuse tool call trace
  • Ground truth per fault step
  • ExperimentRun metadata
→
Phase 0
Bucketing
  • Split trace by fault windows
  • Tag each call: in-fault / baseline
  • Build per-fault sub-traces
→
Phase 1
Classification
  • LLM-as-judge per tool call
  • Labels: DETECT / REMEDIATE / IRRELEVANT
  • Match against expectedSymptoms
  • Identify first DETECT + REMEDIATE
→
Phase 2
Metrics
  • TTD = T(first DETECT) − T₀
  • TTM = T(first REMEDIATE) − T₀
  • Tool call efficiency ratio
  • False positive rate
  • Root cause accuracy
→
Phase 3
Aggregation
  • Per-fault scores weighted
  • Overall composite score
  • Compare vs successCriteria
  • PASS / FAIL / CONDITIONAL
→
Output
Certificate
  • Signed cert if PASS
  • Score + evidence per fault
  • modelUsed + modelProvider
  • Langfuse trace link
Scored Metrics
time_to_detect time_to_mitigate tool_call_efficiency root_cause_accuracy false_positive_rate alert_correlation
All metrics stored per-run. Cross-model comparison is built-in — same experiment, different modelUsed → direct A/B score view.
